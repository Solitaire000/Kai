# 小K（kai_agent）完整迭代优化方案

> 目标：不是"媲美大厂"，而是打造一个**独一无二、真正懂你、能动手办事**的私人助手。
> 核心逻辑：智能上限交给可替换的最强模型去解决；**不可替代性**来自记忆资产、行动能力、系统主权这三样别人复制不走的东西。

---

## 一、北极星原则（后续所有决策的判断标准）

在具体优化项之前，先明确几条贯穿全局的原则，之后每次做技术选型时都可以拿来对照：

1. **调度优于自研** —— 不要试图让本地模型变得更聪明，而要让路由层更聪明。复杂推理永远交给当下最强的可用模型（在线或本地），小K的核心价值不在"脑子"，在"脑子之外的一切"。
2. **文本资产优于权重资产** —— 记忆库、身份锚定、蒸馏语料这些纯文本/结构化数据，才是真正跨模型、跨十年周期保值的东西。LoRA权重、模型文件永远是"可重新编译的产物"，该舍就舍，不要恋战。
3. **能行动优于能对话** —— 一个只会聊天的agent是玩具，一个能读文件、控设备、办实事、可信赖执行的agent才是助手。这是本方案里优先级最高的一条主线。
4. **可回滚优于可高效** —— 任何涉及写入、执行、控制硬件的能力，先保证"错了能撤销、能看清做了什么"，再谈效率和自动化程度。信任是慢慢攒的，一次不可逆的误操作可能让你再也不敢把真事交给它。
5. **数据主权优于功能丰富度** —— 遇到"要不要依赖某个云服务/第三方API来换取便利"的选择时，默认优先本地可控方案，除非云方案的能力差距大到无法替代。

## 二、现状诊断（先说清楚现在缺什么）

| 维度 | 现状 | 缺口 |
|---|---|---|
| 记忆 | 三层记忆系统 + 向量检索，结构完整 | 缺乏使用效果的量化评估，缺少备份/版本化 |
| 智能调度 | model_router 支持在线优先、本地降级 | 降级策略较被动，缺少"该任务用什么模型"的显式策略 |
| 行动能力 | skills 权限分级清晰（只读/需确认/默认关闭） | 全部是被动响应式，没有主动观察-建议闭环 |
| 硬件感知 | mmWave传感器五层架构已落地 | 感知数据尚未接入决策/记忆闭环，处于"能读数"阶段 |
| 可靠性 | 有eval/评测集设计 | 未见自动化回归测试跑起来 |
| 跨模型迁移 | migrate/工具链已设计 | 尚未经历一次真实的换基座模型实战检验 |

## 三、迭代路线图

### 阶段一（近期，1–2个月）：把"骨架"扎稳

这一阶段的核心目的不是加新功能，而是**给已有的复杂设计补上安全网**，因为记忆和权限系统一旦在没有安全网的情况下出错，代价是不可逆的（记忆丢失、误操作硬件/文件）。

**1. 记忆资产的备份与版本化**
- 为什么优先做：`memory/identity/identity_anchors.jsonl` 和 `memory.db` 是整个项目里唯一真正不可再生的东西。模型可以换、代码可以重写，但记忆丢了就是真丢了。这是"地基里的地基"。
- 怎么做：
  - 每次写入后做增量快照（例如按日打包成带时间戳的归档，存到项目外的另一块盘或云端加密备份）
  - 对 `identity_anchors.jsonl` 做Git版本化管理，方便追溯"人格漂移"是什么时候发生的
  - 定义一个"记忆完整性校验脚本"，启动时自动跑一遍，发现损坏及时告警

**2. 让 `data/eval/` 真正跑起来**
- 为什么优先做：现在的架构复杂度已经不低（三层记忆+向量检索+多子agent+路由），复杂系统没有回归测试，意味着你每次改动都在盲改，很容易在自己没发现的情况下破坏记忆一致性或人格一致性。
- 怎么做：
  - 先从最小可用集开始：10~20个"记忆检索准确性"用例 + 5~10个"身份一致性"用例（问同一类问题，人格/语气应保持稳定）
  - 接入到 `start_kai.bat` 或单独脚本，每次重大改动后手动跑一次，逐步过渡到自动触发

**3. 操作审计日志**
- 为什么优先做：你即将扩大高权限skill（write_file、run_command、硬件控制）的使用范围，"敢不敢把真事交给它"取决于出问题时你能不能查清楚它做了什么。这是后续所有"行动能力"升级的前提条件，必须先于阶段二。
- 怎么做：
  - 所有write_file/open_path/run_command/硬件控制类操作，统一写入 `memory/audit_log.jsonl`（时间戳、操作类型、参数、结果、是否用户确认）
  - 提供简单的 `/audit` 命令查看最近操作记录

---

### 阶段二（中期，3–6个月）：从"对话"走向"行动"

这是整个方案里最核心的一步，也是小K区别于任何"聊天工具"的分水岭。

**4. 主动观察-建议闭环**
- 为什么要做：现在的skills全部是"你问它才做"，这不是助手，是查询工具。真正有用的私人助手要能主动发现问题，比如"你上次说的bug我看了下代码，还没改"，或结合传感器数据主动提醒。
- 怎么做：
  - 设计一个轻量的后台观察循环（不是持续跑大模型，而是低成本的规则/小模型触发 + 命中后才唤起主模型）
  - 先从最小场景切入：日程提醒、长时间未处理的TODO提醒、mmWave传感器异常（比如长时间静坐）提醒
  - 严格限制主动打扰频率，避免"话痨助手"反而降低信任感

**5. 跨skill任务编排（任务闭环）**
- 为什么要做：真正省心的助手需要能把"帮我看看今天日程，把明天要交的材料提醒我"这种一句话，拆解成多个skill调用并自动串联，而不是让你自己一步步指挥。
- 怎么做：
  - 在 `agents/base_agent.py` 之上加一层轻量的任务规划器（可以先用主模型做plan，再顺序调用skill，不必自己写复杂的planner）
  - 先支持2~3个高频真实场景闭环（比如"论文材料整理提醒"、"设备状态巡检+异常预警"），验证可行后再扩展

**6. 可信执行反馈机制**
- 为什么要做：这是阶段一"审计日志"的用户可见版本。光有日志你不去看没用，助手做完事得清楚地告诉你它做了什么、依据是什么、有没有不确定的地方。
- 怎么做：
  - 每次执行有风险的操作后，用固定格式反馈："我做了X操作，依据是Y，如果不对可以用Z撤销"
  - 对不确定的判断，明确标注"这一步我不确定，建议你确认"，而不是自信地一口气做完

---

### 阶段三（长期，6–12个月以上）：让优势变成复利

**7. 记忆检索质量的持续优化**
- 为什么要做：记忆系统是你唯一能靠时间积累、大厂无法复制的护城河，值得长期投入而不是搭完就不管了。
- 怎么做：
  - 定期（比如每月）review哪些记忆被高频检索命中、哪些从未被用到，砍掉噪音，强化高价值记忆的权重
  - 逐步引入"记忆重要性衰减/强化"机制，模拟人类记忆的巩固过程，而不是所有记忆权重恒定

**8. 硬件感知到决策的真正打通**
- 为什么要做：目前mmWave传感器还停留在"能读数"阶段，这是小K区别于任何软件agent的核心差异点，值得深挖而不是浅尝辄止。
- 怎么做：
  - 先把传感器数据接入记忆系统，形成"生理状态时间线"
  - 再逐步接入决策层：比如结合作息数据和日程数据，主动建议休息或调整工作节奏
  - 长期可以扩展更多传感器（环境光、噪音等），构建更完整的"环境感知层"

**9. 一次真实的换基座模型演练**
- 为什么要做：`migrate/` 工具链设计得再好，没有真实跑过一次，你不知道哪里会出问题。这是验证"记忆资产是否真的模型无关"的唯一方式，也是这套架构最核心的假设，必须被检验。
- 怎么做：
  - 找一个时间窗口，故意切换到另一个开源基座模型，走一遍完整迁移流程
  - 记录下所有摩擦点，反哺 `migrate/README.md` 和迁移脚本

**10. 子agent"共同进化"架构落地**
- 为什么放最后：`docs/SUBAGENT_COEVOLUTION.md` 里的"总览+咨询+共同进化"设计目标宏大，但依赖前面所有基础设施（记忆、行动、审计）先稳定，否则多agent协同只会放大不稳定性，不建议现在就深入。

## 四、优先级矩阵

| 优先级 | 事项 | 原因 |
|---|---|---|
| P0 | 记忆备份与版本化 | 唯一不可逆损失点 |
| P0 | 操作审计日志 | 后续行动能力升级的前提 |
| P1 | eval回归测试跑起来 | 防止复杂系统盲改出错 |
| P1 | 主动观察-建议闭环 | 从工具走向助手的分水岭 |
| P2 | 跨skill任务编排 | 显著提升实用性 |
| P2 | 可信执行反馈 | 建立"敢用"的信任基础 |
| P3 | 记忆检索质量迭代 | 长期复利，不急于一时 |
| P3 | 硬件感知-决策打通 | 差异化优势，但需要前置基础扎实 |
| P4 | 真实换模型演练 | 验证性工作，可安排在架构稳定后 |
| P4 | 子agent共同进化架构 | 依赖前面所有基础，暂不深入 |

---

## 五、验收标准（怎么知道每个阶段真的做到了）

- **阶段一完成标志**：记忆库有可用的历史快照、审计日志能完整回溯最近一周的高权限操作、eval跑一次不再是手动拼凑。
- **阶段二完成标志**：至少有一个"主动提醒"场景稳定运行不误报、至少有一个跨skill任务闭环能一句话触发完整执行。
- **阶段三完成标志**：换过一次基座模型且记忆/人格无损、传感器数据真正影响过一次决策建议。

---

## 六、写在最后

这套方案里，真正决定小K能不能变成"独一无二、别人复刻不走"的助手的，不是模型多强，而是**阶段一和阶段二**——安全的记忆资产、可信的行动能力。这两点做扎实了，即便未来大厂把"持久记忆"做成标配，你手上的小K依然拥有厂商产品结构性做不到的东西：完全懂你的上下文、能操作你的真实环境、系统逻辑完全由你掌控。这才是"属于自己"这四个字真正的分量所在。
